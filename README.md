# СтрІМ — strim.in.ua

Вихідний код сайту й платформи «СтрІМ» для автоматизації спот-торгівлі на Binance. Імпортовано поточну локальну копію проєкту 15 жовтня 2026 року.

## Структура

- `www/` — сторінки сайту, стилі, зображення, кабінет, авторизація та PHP API.
- `engine/`, `engine_v2/`, `engine_v3/` — торговий рушій, черги та інтеграція з Redis.
- `services/ws/ws_price_cache.py` — сервіс котирувань через WebSocket.
- `run/` — засоби розгортання, обслуговування й міграції схеми.
- `docs/` — документація про продукт та архітектуру.

Окремі експериментальні продукти `acct/` та `shef/` не входять до цього репозиторію. Паролі, ключі, дампи баз даних, робочі журнали, персональні операційні звіти, старі бекапи й установлені залежності залишаються поза Git.

## Середовище

Поточний хостинг використовує PHP 8.4; потрібні розширення `mysqli`, `curl`, `openssl`, `mbstring`, Composer, MySQL та налаштований Redis для відповідного режиму черги. Інтерфейс складається зі статичних HTML/CSS/JS файлів і PHP; окремої збірки через Node.js немає.

Залежності PHP описано в `www/composer.json`. Успадкований `www/composer.lock` ще не містить `predis/predis`, зазначеного в маніфесті: перед відтворенням середовища потрібно узгодити lock-файл. Збережено стан вихідного проєкту без оновлення його залежностей.

Залежності сервісу WebSocket наведено в `services/ws/requirements.txt`. `www/app.py` і `www/passenger_wsgi.py` — збережений Python-компонент із залежностями Flask, ccxt і python-dotenv; його ввімкнення залежить від конфігурації хостингу.

Скопіюй `.env.example` у локальний `.env` та внеси потрібні приватні налаштування. Для існуючого сайту використовуй його чинну конфігурацію. У `run/migrations/` збережено міграції, але повного початкового опису основних таблиць у вихідній копії немає. Копія робочої бази даних переноситься окремо приватним каналом.

## Робота із сайтом

Код змінюється й перевіряється локально. Перед публікацією потрібно звірити версії потрібних файлів на хостингу, зберегти їхні оригінали поза `www/`, опублікувати вибрані файли, перевірити відповідні сторінки та мати можливість відновлення.

`run/deploy_site_files.py` містить механізм вибіркового розгортання з перевіркою контрольних сум, бекапом і відновленням. Його транзакційний механізм перевірено на сервері через WebSSH у приватній тестовій папці. Пряме підключення SSH/rsync із локального середовища наразі відхиляється; підтверджений доступ працює через термінал панелі хостингу. Це не автоматичний деплой із GitHub.

Наявні `STRIM_SETUP.md` і `.github/workflows/strim-access.yml` збережено з початкового репозиторію. Workflow запускається вручну й потребує окремого налаштування секретів GitHub Actions. Саме завантаження коду в GitHub не публікує зміни на робочому сайті.
