# Білінг StrIM: депозит + 10% від реалізованого профіту

**Статус:** cutover live (Owner GO 2026-09-21) — prod `billing_model=percent`  
**Заміна:** фіксована підписка 500 грн / 30 днів  
**Реквізити оплати:** без змін (Privat / Whitepay / ручний notify)

Цей документ — єдине джерело правди для імплементації. Поки статус freeze — не змінювати правила без нового Owner GO.

---

## 1. Модель доступу

### 1.1 Trial (до першого депозиту)
- **Безстроково**, доки немає жодного успішного поповнення ≥ 500 грн.
- Ліміти: **max 3** running стратегії, **FBA ≤ 10 USDT**.
- Після першого депозиту trial-ліміти знімаються назавжди для акаунта.

### 1.2 Funded (`balance_usdt` дозволяє торгівлю)
- **Max 50** running стратегій.
- FBA без продуктової верхньої межі (техмін ≥ 7 USDT лишається).
- Старт / BUY дозволені, поки статус не `exhausted` / `blocked`.

### 1.3 Exhausted (баланс 0 або не покриває політику після shortfall)
- Як колишній EXPIRED wind-down: **немає** нових стартів і докупок; **TP / SELL** дозакривають позиції.
- Кабінет: «Баланс вичерпано — поповніть від 500 грн».

### 1.4 Blocked
- Адмін-блок (як зараз).

## 2. Баланс і депозит

### 2.1 Валюта балансу
- Внутрішній баланс платформи: **USDT** (`users.balance_usdt`).
- Усі комісії, рефералка і депозити після конвертації — у USDT.

### 2.2 Поповнення
- Мінімум: **500 грн** за операцію.
- Реквізити ті самі; сума змінна (≥ 500).
- При зарахуванні:
  1. Курс **Binance** пари USDT/UAH (напр. `USDTUAH` ticker) **на момент зарахування**.
  2. `amount_usdt = amount_uah / price` **або** за фактичним напрямком котирування пари — зафіксувати в коді одну формулу й unit-тест.
  3. Ledger: `type=deposit`, `amount_uah`, `fx_rate`, `amount_usdt`, `payment_ref`, `created_at`.
  4. `balance_usdt += amount_usdt`.
- Курс **не** переоцінюється щодня після зарахування.

### 2.3 Відображення в кабінеті
- Поточний баланс USDT.
- Історія: депозити (грн + курс + USDT), комісії 10%, реферальні кредити, адмін/міграція, погашення shortfall.
- Прев’ю перед оплатою: «N грн ≈ X.XX USDT (курс Binance …)».

### 2.4 Вивід коштів з балансу
- **Звичайного виводу депозиту немає.**
- Повернення — **лише** у випадках, прямо описаних в оферті / returns.
- Реферальні нарахування йдуть на **той самий баланс** і слугують для покриття комісії 10% (див. §4); окремий «кеш-аут рефералки» у цьому freeze **не робимо** (якщо з’явиться пізніше — окремий Owner GO).

## 3. Комісія платформи 10%

### 3.1 База
- Лише **позитивний реалізований** PnL з `trade_ledger` (події SELL з `pnl_usdt > 0`), після фактичного fill (не WS-тік).
- Угоди з `pnl_usdt ≤ 0`: комісія **0**.

### 3.2 Момент і формула
- На **кожному +SELL**, одразу після успішного запису в ledger.
- `fee_usdt = pnl_usdt * 0.10` (округлення: до 8 знаків у ledger, UI до 2–4).
- Ідемпотентність: UNIQUE на `trade_ledger_id` у fee-проводках.

### 3.3 Shortfall (нестача балансу)
- Списати `min(fee, balance_usdt)`.
- Залишок боргу зберегти як `fee_shortfall_usdt` (на юзері та/або ledger `type=fee_shortfall`).
- Статус → exhausted, pause нових входів.
- **Наступне поповнення автоматично погашає shortfall** (спочатку борги комісії, потім зростання доступного балансу).

Приклад: fee 10, balance 3 → списуємо 3, shortfall 7, exhausted; депозит +21.47 USDT → −7 shortfall, balance ≈ 14.47.

## 4. Реферальна програма

| Параметр | Правило |
|----------|---------|
| База | **20% від USDT-еквівалента** депозиту реферала (`amount_usdt` тієї ж проводки deposit) |
| Accrual | У момент зарахування депозиту реферала (очікуване нарахування) |
| Settlement на баланс | **01 та 16** числа кожного місяця (за період з попередньої дати settle) |
| Куди | Той самий `balance_usdt`, `type=referral_credit` |
| Призначення | Покриття **власної** торгової комісії 10% (і загальний баланс funded) |

Стара модель «20% від номіналу підписки 10 USDT» — скасовується з дати cutover.

## 5. Міграція існуючих клієнтів

### 5.1 Кому нарахувати стартовий баланс
- Лише користувачі, які **мали оплату / статус active** (ефективний доступ за старою підпискою на момент cutover: `billing_status=active` та/або валідний `paid_until` у майбутньому — точна SQL-умова в міграційному скрипті).
- **Не** нараховувати автоматично чистим trial / expired без історії оплати.

### 5.2 Що нарахувати
- Еквівалент **500 грн → USDT** за курсом Binance **на момент запуску міграційного скрипта**.
- Ledger: `type=migration_credit`, `amount_uah=500`, `fx_rate`, `amount_usdt`.

### 5.3 Після cutover
- Доступ керується балансом / trial-лімітами, не `paid_until`.
- Поля `paid_until` / `trial_until` можна лишити для аудиту або deprecated.

### 5.4 Адмін-кнопка
- Замість **+30 днів / 10 USDT** → кнопка **+500 грн**.
- Дія: курс Binance → `+balance_usdt`, ledger `type=admin_credit` (або `admin_deposit`).

## 6. Платіжні рейки

1. **Privat UAH** — змінна сума ≥ 500; після підтвердження транзакції → deposit + FX snapshot.  
2. **Whitepay** — інвойс у грн на введену суму ≥ 500.  
3. **Ручний payment_notify** — адмін підтверджує грн; система тягне Binance FX і кредитує USDT.  
4. При будь-якому депозиті: якщо є `fee_shortfall_usdt` > 0 — **спочатку погасити shortfall**.

---

## 7. Кабінет і адмінка (чеклист UX)

**Кабінет**
- Баланс USDT + статус (trial / funded / exhausted)
- Поповнити (≥ 500 грн) + прев’ю курсу
- Історія ledger
- Профіт + комісія 10% за період
- Рефералка: очікувані accrual, дати 01/16, уже на балансі
- Банер exhausted

**Адмін**
- +500 грн
- Перегляд балансу / ledger / shortfall
- Block, max bots
- Підтвердження ручних платежів
