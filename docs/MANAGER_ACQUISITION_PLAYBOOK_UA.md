## 1. Короткий висновок дослідження

Перед підготовкою матеріалів проаналізовано три лінії досвіду:

| Джерело | Що працює | Чого StrIM **не** копіює |
|---------|-----------|--------------------------|
| **RoyalQ / крипто-боти з ком’юніті** | Особистий супровід у Telegram, покрокове підключення API, «VIP-чат» для новачків, список із 100 контактів, відео-інструкції | MLM-рівні, обіцянки «пасивного доходу», гарантований % прибутку |
| **SaaS Customer Success** (Gainsight, Velaris, Pulse) | Перші 30 днів — критичні; метрика Time-to-First-Value; co-build замість «90 слайдів»; чекпоінти День 0 / 7 / 14 / 30 | Enterprise-складність — у нас простіший продукт |
| **Crypto affiliate compliance** (MiCA, Track360) | Чітка подія конверсії, затвердження креативів, навчання партнерів, антифрод, дисклеймери ризиків | Обіцянки гарантованого прибутку = бан реклами + юридичний ризик |

**Висновок для StrIM:** менеджер — це не «продавець мрії», а **провідник + Customer Success на 30 днів**: допомогти людині пройти шлях *реєстрація → API → перша стратегія → оплата підписки* без токсичних обіцянок.

## 3. Мотивація та умови (випробувальний період)

### 3.1. Базова схема (як ви задали)

| Параметр | Умова |
|----------|--------|
| Випробувальний період | До досягнення **50 діючих платних клієнтів**, яких запросив менеджер |
| Винагорода на випробувальному | **2 USDT** за кожного **запрошеного** користувача, який **оформив і оплатив підписку** |
| Після 50 клієнтів | Додаткова **фіксована ставка** + **офіційне працевлаштування** (деталі — окремий договір) |

### 3.2. Визначення «діючого платного клієнта» (для нарахування)

Клієнт зараховується менеджеру, якщо **одночасно**:

1. Зареєструвався за **персональним реф-кодом менеджера** (`signup_ref_code_used` у кабінеті / адмінці).
2. **Оплатив** підписку 500 грн / 30 днів (WhitePay, банк, USDT — не важливо, головне — підтверджена оплата в системі).
3. Підписка **активна** (не просто trial без оплати).
4. Це **не** self-referral (менеджер не реєструє себе / родичів без реальної торгівлі).
5. Клієнт **не повернув** оплату протягом 7 днів після першої оплати (утримання clawback).

**Не рахується:** лише реєстрація, лише trial 3 дні без оплати, фейкові email, дублікати акаунтів.

### 3.2.1. Математика випробувального
- 50 клієнтів × 2 USDT = **100 USDT** максимум на етапі CPA (без фіксу).
- Це **окремо** від реферальної програми для звичайних користувачів (20% від оплати в USDT).

### 3.3. Виплати менеджерам
- Валюта: **USDT BEP-20** (BSC), як і реферальні виплати StrIM.
- Періодичність: **2 рази на місяць** (1–5 і 15–20 число) після звірки з адмінкою.
- Менеджер подає **BSC-адресу гаманця** + звіт (шаблон — розділ 12).
- Перша виплата — після **перших 5** підтверджених платних клієнтів (захист від одноразових «накруток»).

### 3.4. Після випробувального (орієнтир для договору)

Рекомендована структура (узгодити з бухгалтерією):

| Компонент | Орієнтир |
|-----------|----------|
| Фікс (офіційно) | Мінімальна ставка за супровід портфеля (наприклад, від 8 000–12 000 грн/міс — **уточнити**) |
| Бонус за утримання | +0,5 USDT за клієнта з **другою** оплатою підряд |
| Бонус за якість | +X% якщо NPS / відсутність скарг |
| KPI місяця | 10+ нових платних + retention > 60% на 2-й місяць |

*Цифри фіксу — на ваше рішення; у playbook зафіксовано логіку, не остаточний контракт.*

## 4. Технічна атрибуція (обов’язково перед стартом)

### 4.1. Персональний реф-код кожному менеджеру

Формат: `MGR` + ініціали або номер, наприклад `MGRIVAN`, `MGR01`, `MGROLENA`.

**Посилання для поширення:**
```
https://strim.in.ua/auth/register.php?ref=MGR01
```

Код підставляється в поле «Реферальний код» автоматично.

### 4.2. Що зробити адміністратору StrIM перед наймом

1. Створити менеджеру **службовий акаунт** StrIM (email компанії).
2. У `users` призначити унікальний `ref_code` (наприклад `MGR01`).
3. Перевірити в адмінці (`/admin/users.php`), що нові реєстрації з `signup_ref_code_used = MGR01` видно.
4. Вести **Google Sheet / Notion** «Менеджер → клієнт → дата оплати → статус».
5. (Опційно, етап 2) Окрема таблиця `manager_rewards` у БД — поки достатньо ручної звірки на 3–5 менеджерів.

### 4.3. Антифрод

- Заборона реєструвати «своїх» без торгівлі.
- Один menеджер — один Telegram для зв’язку з командою (верифікація).
- Підозрілі патерни (10 реєстрацій / година, example.com email) — стоп, звіт керівнику.
- Креативи **тільки** з цього playbook або погоджені керівником.
